# Security reporting

Use the repository's private vulnerability reporting feature on GitHub if enabled. If unavailable, ask the maintainer to establish a private reporting channel without posting exploit details, recordings, transcripts, credentials or machine-specific evidence in a public issue.

Whispering is currently a 0.1.0 prerelease. No production support or patch-response deadline is promised yet. Before a production release, the maintainer must publish supported versions, a monitored private contact and response/remediation deadlines. Do not interpret CI or package signatures as completion of a security assessment.

Keep reports and audits outside Git; sanitized threat-model and reporting documentation may be committed. Never attach real voice recordings or user profile data to public reports.
